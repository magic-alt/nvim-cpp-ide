# IDE ↔ Agent Context Bridge

The context bridge exports Neovim runtime state into a small, provider-neutral project-local snapshot that external coding agents can read without requiring an editor-specific SDK.

The default output is:

```text
.nvim-agent/
├── .gitignore      # contains `*`; runtime output stays out of Git
├── context.json    # stable machine-readable interface
└── context.md      # human/agent-readable mirror
```

The directory is created on demand. No daemon, database, provider API, or background service is required.

## Commands

With `NVIM_CPP_IDE_PROFILE=agent`:

```vim
:AgentContext
:AgentContextOpen
:AgentContextPrint
```

- `AgentContext` refreshes both files.
- `AgentContextOpen` refreshes the snapshot and opens `context.md`.
- `AgentContextPrint` collects the same schema without writing files; in headless mode it prints compact JSON to stdout.

Launching a registered agent also refreshes the snapshot automatically:

```vim
:Agent codex
:Agent claude
:Agent gemini
```

The CLI still runs as an external process at the detected project root. Neovim does not inject provider prompts, credentials, models, or API settings.

## Snapshot schema

`context.json` uses a versioned top-level contract:

```json
{
  "schema_version": 1,
  "generated_at": "2026-09-02T00:00:00Z",
  "runtime": {},
  "project": {},
  "current": {},
  "diagnostics": {},
  "git": {},
  "task_results": {},
  "quickfix": {}
}
```

### `runtime`

Includes:

- active nvim-cpp-ide profile;
- Neovim version;
- whether the collector is running headless.

### `project`

Reuses the Project Task Engine and records:

- repository-relative root (`.`);
- detected backend;
- optional project task config;
- resolved `configure`, `build`, `test`, `lint`, and `format` tasks;
- argv arrays and repository-relative working directories.

Machine-specific absolute project paths are not persisted. Absolute paths outside the project are reduced to an external-path marker plus basename.

### `current`

Includes:

- current project-relative file;
- filetype;
- modified-buffer state;
- cursor line/column;
- a best-effort current symbol hint.

The symbol collector prefers an available Tree-sitter node and falls back to the cursor word. It is advisory rather than a semantic index.

### `diagnostics`

Collects project-local diagnostics from buffers currently loaded in Neovim, including:

- file;
- line/column;
- severity;
- source/code when available;
- diagnostic message.

The default cap is 200 entries so a pathological diagnostic flood does not create an unbounded context file.

### `git`

Uses the local Git CLI when available and records:

- branch and short HEAD;
- dirty/clean state;
- changed-file status entries;
- staged and unstaged line-count summaries;
- staged and unstaged changed-file lists.

The bridge intentionally does **not** persist the full patch. Agents should run `git diff` themselves when they need exact code changes.

### `task_results`

The Project Task Engine keeps the most recent result for each action in the current Neovim session. The snapshot can therefore expose the last known:

```text
configure
build
test
lint
format
```

Each result contains action/backend, portable argv/cwd, exit code, signal, and completion timestamp.

Task history is runtime state, not a cross-process database. If a headless workflow needs build/test results in the snapshot, run them in the same Neovim process before exporting context.

### `quickfix`

Exports the current Quickfix title and up to 100 entries with project-relative location, type, message, and validity.

This gives an agent a compact view of compiler/parser/tool failures already surfaced to the human developer.

## Interactive workflow

A typical terminal workflow becomes:

```text
Neovim
  │
  ├── clangd diagnostics
  ├── Quickfix
  ├── ProjectTask build/test
  ├── Git working tree
  └── current file/symbol
          │
          ▼
     :AgentContext
          │
          ▼
.nvim-agent/context.json
.nvim-agent/context.md
          │
          ▼
Codex / Claude Code / Gemini CLI
```

Because `:Agent <name>` refreshes the snapshot before spawning the CLI, the normal path is simply:

```vim
:Agent codex
```

When `AGENTS.md` was generated by `:AgentInit`, it tells compatible agents that `.nvim-agent/context.json` / `context.md` are advisory runtime snapshots.

## Headless / CI deployment

The bridge has no plugin-specific runtime dependency and can be used with the normal modular config in headless Neovim.

Export current project state:

```bash
cd /path/to/project
NVIM_CPP_IDE_PROFILE=agent \
  nvim --headless -u ~/.config/nvim/init.lua \
  '+AgentContext' +qa
```

Include a particular source file as current focus:

```bash
NVIM_CPP_IDE_PROFILE=agent \
  nvim --headless -u ~/.config/nvim/init.lua \
  '+edit src/main.cpp' \
  '+AgentContext' +qa
```

Include task results in the same snapshot:

```bash
NVIM_CPP_IDE_PROFILE=agent \
  nvim --headless -u ~/.config/nvim/init.lua \
  '+edit src/main.cpp' \
  '+ProjectTask build' \
  '+ProjectTask test' \
  '+AgentContext' +qa
```

Failed headless project tasks retain the existing Project Task Engine behavior and return a non-zero process exit code.

## SSH, container, and worktree deployment

The context bridge is deliberately filesystem-based:

- **SSH**: run Neovim and the agent CLI in the remote checkout; both see the same `.nvim-agent/` directory.
- **Container**: mount the repository normally; no separate socket or host service is required.
- **Git worktree**: every worktree gets its own `.nvim-agent/` snapshot because output is rooted in the detected project/worktree directory.
- **CI**: call headless Neovim after or around deterministic `ProjectTask` validation.

The standard installers already copy the entire modular `lua/` tree recursively, so no new installation step is required for the context modules.

## Git hygiene

The exporter creates:

```text
.nvim-agent/.gitignore
```

with:

```gitignore
*
```

This makes the whole runtime directory disposable and prevents context refreshes from polluting the project's Git status without modifying the repository-root `.gitignore`.

## Privacy and scope

By default the persisted snapshot omits:

- source-file contents;
- full Git patches;
- environment variables;
- provider credentials/API keys;
- machine-specific project-root paths;
- terminal scrollback;
- arbitrary shell history.

Diagnostics and Quickfix messages can still contain project-specific text, so `.nvim-agent/` should be treated as local runtime data and not uploaded or committed.

## Limits

The first context bridge is intentionally bounded:

- only loaded-buffer diagnostics are exported;
- symbol focus is best-effort, not a full semantic stack trace;
- Git exports summaries and changed paths, not full diff hunks;
- task history lasts for the current Neovim process;
- there is no automatic conflict resolution or patch acceptance yet.

Those boundaries keep the bridge deterministic and provider-neutral. The next review-oriented roadmap layer can build diff-first review and external-file conflict UX on top of this stable snapshot contract.
